# ICSI620 — Тоног төхөөрөмжийн захиалгын суурь код

Нэмэлт npm сан, IoT төхөөрөмж, өгөгдлийн сан суулгахгүй. Node.js 22 эсвэл түүнээс дээш шаардлагатай. Код нь JavaScript ES modules; TypeScript руу хөрвүүлэхээс өмнө шууд ажиллуулж архитектурын заагийг судлах жижиг суурь юм.

## 1. Ажиллуулах (Windows, macOS, Linux)

ZIP-ийг задлаад `icsi620-starter` хавтсыг VS Code-оор нээ. Terminal дээр:

```sh
node --version
npm start
```

Browser: http://127.0.0.1:3000

`npm install` шаардлагагүй. Зогсоох: Ctrl+C. PowerShell `npm.ps1`-ийг хоригловол `node src/server.js` ашигла. Порт 3000 завгүй бол өмнөх процессыг зогсоо.

## 2. Туршилт

```sh
npm test
```

PowerShell хувилбар: `node --test`. Тест тус бүр тусдаа сервер, санах ойн өгөгдөлтэй. Тестийн порт автоматаар сонгогдоно; үндсэн серверийг асаах шаардлагагүй.

Автомат шалгалт: давхардал, залгаа интервал, өөр төхөөрөмж, цуцлалт, давтан цуцлалт, буруу хугацаа, unavailable/олдохгүй төхөөрөмж, зэрэгцээ 10 хүсэлт.

## 3. Browser дээр 4 кейс шалгах

Бүх цаг нэг өдрийн UTC цаг байна. Кейс бүрийг тусдаа эхний төлөвөөс шалга; серверийг дахин асаахад захиалга цэвэрлэгдэнэ.

| Өмнөх захиалга | Шинэ хүсэлт | Хүлээлт |
|---|---|---|
| EQ-01, 10:00–11:00, active | EQ-01, 10:30–11:30 | 409 |
| EQ-01, 10:00–11:00, active | EQ-01, 11:00–12:00 | 201 |
| EQ-01, 10:00–11:00, active | EQ-02, 10:30–11:30 | 201 |
| EQ-01, 10:00–11:00, cancelled | EQ-01, 10:30–11:30 | 201 |

## 4. API

| Method / path | Үүрэг |
|---|---|
| GET /equipment | Жишээ төхөөрөмжийн жагсаалт |
| GET /reservations | Захиалгын жагсаалт |
| POST /reservations | Захиалга үүсгэх |
| POST /reservations/R-1/cancel | Цуцлах |
| GET /notifications | Локал мэдэгдлийн бүртгэл |

POST /reservations JSON:

```json
{"equipmentId":"EQ-01","userId":"U-01","startAt":"2026-10-05T10:00:00Z","endAt":"2026-10-05T11:00:00Z"}
```

Амжилт 201: `reservationId`, `id`, талбарууд, `status: active`. Алдаа 400/404/409: `code`, `message`. Интервал `[startAt,endAt)`; төгсгөлдөө залгаа захиалга зөвшөөрнө. ISO timestamp нь Z эсвэл timezone offset-той байна; хадгалахдаа UTC болгоно. userId нь хоосон биш string байхыг л шалгана; хэрэглэгчийн сан байхгүй.

## 5. Модуль

- `src/catalog.js`: төхөөрөмжийн жагсаалт, төлөвийн уншилт.
- `src/booking.js`: захиалгын өгөгдөл, интервалын дүрэм, цуцлалт.
- `src/notification.js`: синхрон локал бүртгэл; бодит имэйл илгээхгүй.
- `src/server.js`: HTTP гэрээ, алдаа хөрвүүлэх; бизнесийн дүрэм Booking-д байна.
- `src/index.html`: энгийн интерфэйс; бүх бизнесийн шалгалтыг сервер хийдэг.
- `test/api.test.js`: функциональ API шалгалт. Гүйцэтгэлийн benchmark биш.

## 6. Суурийн хязгаар ба туршилтын нөхцөл

Өгөгдөл RAM-д байна; restart хийхэд захиалга, мэдэгдэл арилна. Нэг процесс, нэг instance. Давхардал шалгах ба хадгалах хооронд await байхгүй тул энэ суурийн нэг процесс дотор зэрэгцээ хүсэлтүүд зөрчил үүсгэхгүй. Өгөгдлийн сангийн async үйлдэл эсвэл олон instance нэмэхэд энэ баталгаа үйлчлэхгүй; транзакц/түгжээ/өгөгдлийн сангийн хязгаарлалт хэрэгтэй.

Мэдэгдэл синхрон бүртгэгддэг. Мэдэгдлийн алдаа гарвал захиалгыг буцаахгүй; серверийн console-д алдаа бичнэ. Retry, persistent queue, хүргэлтийн баталгаа байхгүй. Энэ сонголтыг оюутан ADR-аар хэлэлцэнэ.

Нэвтрэлт, эрхийн шалгалт, хадгалалт, аудит, бодит имэйл байхгүй. Сервер зөвхөн 127.0.0.1 дээр ажиллана. Энэ нь локал сургалтын суурь; олон хэрэглэгчийн бодит үйлчилгээ болгох бэлэн систем биш.

## 7. Оюутны 1-р хичээлийн ажил

1. Кодыг ажиллуулж 4 кейсийн expected/actual үр дүнг тэмдэглэ.
2. Component зураг гаргаж өгөгдлийн эзэмшил, модуль хоорондын дуудлагыг тайлбарла.
3. Нэг процессын сонголтод өөрийн ADR-001 бич. Ашиг, өртөг, дахин авч үзэх нөхцөл оруул.
4. Гүйцэтгэл ба мэдэгдлийн доголдлын хоёр хэмжигдэхүйц сценари бич.
5. Sync/async мэдэгдлийг харьцуулах асуулт, тогтмол нөхцөл, хэмжүүрийг төлөвлө. Өнөөдөр async хэрэгжүүлэх шаардлагагүй.
6. AI ашигласан бол аль хэсэгт, хэрхэн шалгаснаа тэмдэглэ. Хүн бүр нэг дүрэм, нэг шийдвэрийг өөрөө тайлбарлана.

Бүх баг энэ ижил ZIP-ээс эхэлнэ. Анхны хувилбараа хадгалж, өөрчлөлтөө тусдаа Git commit/branch-д хий. `npm test` ногоон болох нь p95, scalability, reliability шаардлага батлагдсан гэсэн үг биш. Хэмжээгүй үр дүнг тайлагнахгүй.
